# 保底手艺：交互、动效与细腻感

静态截图好看只是一半。页面「单薄、平淡」，多数时候不是配色的问题，而是：**只设计了默认状态**、点了没反应、东西生硬地出现和消失、没有层次和细节。

这份文件给的是默认值和清单。和 `floor-web-ui.md` 一样：没有理由时照着做，有理由时可以打破。

> 细腻 ≠ 动画多。目标是让每一次操作都有回应，而不是让页面一直在动。

---

## 1. 状态：每个元素不只一种样子

**可交互元素**（按钮、链接、卡片、输入框、开关、标签页）按实际用途覆盖相关状态：

| 状态 | 默认做法 |
|---|---|
| 默认 | — |
| 悬停 hover | 明度或背景变化一档；可点卡片可上移 1–2px 并加深阴影 |
| 按下 active | `transform: scale(0.97–0.98)` 或明度再深一档，60–100ms |
| 键盘焦点 focus-visible | 清晰的焦点环：`outline: 2px solid var(--accent); outline-offset: 2px`。不要只写 `outline: none` |
| 禁用 disabled | 降低对比度（约 40–50% 不透明度），`cursor: not-allowed` |
| 加载中 loading | 按钮内显示小转圈或进度，保持按钮宽度不变，防止重复点击 |
| 选中 / 激活 | 和悬停明显不同（例如强调色指示条），不能只靠颜色深浅一点点 |

**数据区域**（列表、表格、卡片流、搜索结果）都要考虑：

- **空状态**：一句说明 + 一个下一步动作，可以配一个简单的图形。不要只留一片空白。
- **加载状态**：骨架屏，尺寸和真实内容一致，避免加载完成后布局跳动。
- **错误状态**：说清楚发生了什么、用户能做什么（重试按钮），语气平实。
- **极端内容**：超长标题（截断加省略号或换行）、超长数字、只有一条和有一千条的情况。

页面里如果能切换状态（演示用），优先把最有代表性的几个状态都做出来。

## 2. 反馈：每个动作都有回应

- **100ms 内必须有视觉反应**（按下态、加载态）。超过 1 秒显示进度指示；超过约 10 秒显示具体进度或允许后台进行。
- **乐观更新**：点赞、收藏、勾选这类操作立即改变界面，失败再回退并提示。
- **操作结果要看得见**：保存后显示「已保存」并淡出；复制按钮的图标短暂变成对勾；删除后给「撤销」入口（比二次确认弹窗更好）。
- **表单**：标签始终可见（不要只用占位符当标签）；在离开字段时校验，不在每次按键时报错；出错时保留用户已输入的内容，错误信息放在字段旁边并说明怎么改。
- **键盘**：Enter 提交，Esc 关闭弹层，Tab 顺序与视觉顺序一致；弹窗打开时焦点进入弹窗，关闭后回到触发按钮。

## 3. 动效系统：先定 token

和颜色一样，动效先定一组变量，全站复用：

```css
:root {
  --dur-1: 120ms;  /* 微反馈：hover、按下、开关 */
  --dur-2: 200ms;  /* 常规：展开、切换、提示出现 */
  --dur-3: 320ms;  /* 较大元素：抽屉、弹窗、卡片展开 */
  --dur-4: 480ms;  /* 页面级、首屏进场 */

  --ease-out: cubic-bezier(0.2, 0.8, 0.2, 1);    /* 进场、大部分情况 */
  --ease-in: cubic-bezier(0.4, 0, 1, 1);         /* 退场 */
  --ease-in-out: cubic-bezier(0.65, 0, 0.35, 1); /* 位置移动、来回切换 */
  --ease-spring: cubic-bezier(0.34, 1.4, 0.64, 1); /* 轻微回弹：开关、点赞，少用 */
}
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 1ms !important; transition-duration: 1ms !important; }
}
```

规则：

- **位移和淡入淡出优先用 `transform` 和 `opacity`**。折叠区需要推动后续内容时可以过渡布局，检查实际流畅度。阴影变化可以用伪元素的 opacity 实现。
- **退场比进场快**（约为进场时长的 70%）。
- **运动要有因果和方向**：抽屉从它所在的一侧滑出；弹窗从触发按钮附近放大出现；删除的项向外淡出，其余项补位。
- **一次只有一个运动焦点。** 列表依次进场时，间隔 30–60ms，最多前 6–8 项错开，后面的直接出现。
- **位移要小**：进场位移 8–24px 就够了，配合透明度 0→1。大幅度飞入显得廉价。
- **不要循环动画抢注意力**（持续呼吸、浮动、闪烁）。只有表示「正在进行」的东西（加载、直播中）才循环。

## 4. 微交互：让页面「活」起来的小处

按需选用，不必全上：

- **标签页 / 分段控件**：选中指示条在选项之间滑动，而不是瞬间跳。
- **展开收起**：用 `grid-template-rows: 0fr → 1fr` 过渡实现高度动画，箭头图标同步旋转。
- **开关、复选框**：滑块带轻微回弹；勾选用描边动画画出对勾。
- **数字变化**：用 `font-variant-numeric: tabular-nums` 防止数字宽度跳动；重要数字可以做 300–600ms 的计数过渡。
- **链接**：下划线从左向右展开，或下划线颜色和粗细变化。
- **图片**：加载完成后淡入；预留宽高比（`aspect-ratio`），防止布局跳动。
- **滚动进场**：用 IntersectionObserver，**只触发一次**，只用在少数关键区块，不要让每个元素都飞进来。
- **吸顶导航**：滚动后高度略收、背景出现，过渡平滑。
- **页面或视图切换**：支持时可用 View Transitions API（`document.startViewTransition`），让共享元素平滑过渡。
- **光标**：可点元素 `cursor: pointer`；可拖拽元素 `grab / grabbing`。

## 5. 细腻感：静态画面里的精细处

很多「高级感」来自这些看不太出来、但缺了就粗糙的细节：

- **发丝线**：边框用半透明色（如 `rgb(0 0 0 / .08)`），比实色灰线更柔和。
- **深色表面的顶部高光**：`box-shadow: inset 0 1px 0 rgb(255 255 255 / .06)`，让面板有一点厚度。
- **分层阴影**：一层贴近的小阴影加一层扩散的大阴影，比单层阴影真实。
- **嵌套圆角**：外层圆角 = 内层圆角 + 内边距，否则内外圆角看起来不平行。
- **光学对齐**：图标和文字垂直居中时看着要齐，不是数值上齐；播放三角形向右挪一点才显得居中。
- **排版细节**：标题用 `text-wrap: balance`，正文用 `text-wrap: pretty`，避免孤字；数字用等宽数字；英文引号用弯引号。
- **选中文本颜色**：`::selection` 用品牌色的浅版。
- **滚动条**：深色页面上调暗滚动条（`scrollbar-color`），避免一条刺眼的浅色滚动条。
- **输入框光标颜色**：`caret-color: var(--accent)`。
- **移动端**：去掉点击高亮（`-webkit-tap-highlight-color: transparent`），但自己提供按下态。
- **页面标题和图标**：设置有意义的 `<title>` 和 favicon（可以用内联 SVG）。

## 6. 动效性格要跟方向一致

动效也是风格的一部分。参考：

| 方向气质 | 动效性格 |
|---|---|
| 理性、网格、仪器 | 短、准、线性或强 ease-out，几乎不回弹；像机械指针 |
| 档案、报纸、编辑 | 克制，以淡入和轻微位移为主；像翻页、纸张滑入 |
| 东方留白、柔和生活 | 慢（300–600ms）、柔和淡入，没有回弹 |
| 剪纸、孟菲斯、儿童 | 有弹性，可以稍微夸张，形状可以轻微摆动 |
| 粗野主义 | 瞬间切换或极短，硬切本身就是风格 |
| 木刻、暗房、胶片 | 少量、有颗粒感的闪切或叠化 |

同一个页面里，动效性格只有一种。

## 7. 走查：用用户的身份过一遍

截图只能看到静态画面。完成后，按主要任务的顺序走一遍：

1. **第一次打开**：首屏进场是否自然？有没有布局跳动？
2. **完成主要操作**：每一步点下去有没有反应？结果是否看得见？
3. **出错**：输入错误、网络失败时，用户知道怎么办吗？
4. **空状态和极端内容**：没有数据、内容超长时，页面还成立吗？
5. **只用键盘**：Tab 能走到所有可交互元素吗？焦点看得见吗？
6. **窄屏**：390 宽度下，点击目标够大吗？悬停才出现的信息在触屏上能看到吗？

按 [Codex 渲染与检查](codex-rendering.md) 选择当前工具。用浏览器实际操作并查看焦点、展开或错误等关键状态。当前工具支持减弱动效模拟时，也验证该模式下流程是否可用。无法渲染时，在代码中检查相关状态，并在交付时说明实际验证范围。

## 交付前自查（交互部分）

- [ ] 可交互元素都有 hover、active、focus-visible 状态，焦点环看得见
- [ ] 主要操作 100ms 内有反应，结果看得见（已保存、已复制、可撤销）
- [ ] 数据区域有空、加载、错误状态；加载完成后布局不跳
- [ ] 动效复用 token，检查布局过渡的流畅度，退场比进场快
- [ ] 没有持续循环抢注意力的动画；加了 prefers-reduced-motion
- [ ] 动效性格和视觉方向一致
- [ ] 至少一处让人觉得「做得用心」的微交互，而不是所有地方都在动
