# Codex 渲染与检查

按本次会话提供的工具选择路径。工具名称、浏览器 ID 和可用能力可能变化；先读实际工具说明，不把某台机器的配置当作固定前提。

## 网页、UI、SVG 与浏览器中的 3D

1. 有浏览器工具时，用它打开正在开发的页面并截图。当前 Codex 桌面会话可通过 `mcp__cua_repl` 使用 `cua`；首次调用遵循该工具的初始化规则，读取返回文档后再操作。不要另起 shell 浏览器或外部 Playwright 绕过当前浏览器工具的使用约束。
2. 本地网页复用项目已有的开发 / 预览命令和服务器。在浏览器文档提供本地开发说明时先读它；确认浏览器与服务器的可达地址，不预设两者共享文件系统，也不预设 `file://` 可用。
3. 当前浏览器接口提供 `tab.getScreenshot()`；读取浏览器文档后，也可用其提供的 `tab.screenshot({ fullPage: true })`。只调用实际已公布的 API。长页面配合分段截图检查，不能只看缩小后的整页图。
4. 响应式检查用浏览器公布的 viewport capability：先读取能力说明，再设置 1440 / 390 的宽度，检查后恢复临时设置。CSS 模拟手机外框或把截图缩小不算改变视口。若工具无法设置尺寸，记录实际查看的尺寸和未验证的断点，不声称全部通过。
5. 截图中确认字体、图片与核心内容实际出现；再检查交互状态，如菜单展开、表单错误、焦点和移动端导航。浏览器 DOM / 控制台可辅助定位问题，最终以渲染图判断观感。

## 其他媒介

- DOCX、PDF、演示文稿、电子表格：使用对应已提供 skill 的渲染或预览流程，检查真实导出结果，不用 HTML 重画一份冒充检查。
- 独立 SVG：用现有转换工具渲染为 PNG 后查看，或经允许的本地预览服务器在浏览器中查看；文本和滤镜应检查实际渲染。
- 图像生成：用当前图像生成工具及适用 skill，检查返回图像；已有 SVG、图标或代码绘图适合直接编辑时，沿用其原生形式。
- 3D / 动画：检查代表帧和关键状态；支持时看实际运动，单帧截图不能证明节奏和交互正常。

## 工具缺失时

没有浏览器工具且当前规则允许本地渲染时，可复用项目已安装的 Playwright 或现成渲染命令。不要为截图自动运行 `npx -y`、下载浏览器或改系统配置；先检查已有依赖，确有必要时再按任务范围及当前权限处理安装。

仍不能渲染时完成可做的工作，交付中说明未亲眼验证的画面或尺寸。不要为了满足检查清单编造截图、通过结果或阻塞已经能完成的工作。
